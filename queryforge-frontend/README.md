# QueryForge 前端

QueryForge 的 Web 前端:基于 Vue 3 + Vite 的 SSE 实时聊天界面,接收后端 `/api/query` 的流式响应,
逐步渲染「Agent 处理阶段 → 结果表格 → ECharts 图表」,并支持多轮对话(会话记忆)。

## 技术栈

| 项        | 技术                        |
|-----------|----------------------------|
| 框架       | Vue 3(`<script setup>` SFC) |
| 构建       | Vite 7                     |
| 图表       | ECharts                    |
| Excel 导出 | SheetJS                    |
| 通信       | SSE(fetch + ReadableStream 逐块解析) |

## 快速开始

```bash
npm install
npm run dev        # http://localhost:5173
```

Vite 已配置 `/api` 代理到 `http://localhost:8000`(后端),开发时前后端跨域由代理解决,无需额外配置。

## 功能说明

### 消息类型(对应后端 SSE 事件)

| 前端类型     | 后端事件                 | 渲染方式                            |
|------------|------------------------|-----------------------------------|
| `steps`    | `{"stage": ...}`        | 步骤条:每收到一个阶段事件追加一步,当前步骤黄色圆点,完成变绿 |
| `table`    | `{"result": [...]}`     | 结果表格(列名取自结果第一行键)               |
| `chart`    | `{"chart": {...}}`      | 在对应表格上方叠加 ECharts 图表(见下)       |
| `text`     | `{"answer": "..."}`     | 非查询问题的助手文本回答                    |
| `error`    | `{"error": ..., "detail": ...}` | 错误气泡,可展开查看技术细节(可折叠)       |
| `session_id` | `{"session_id": "..."}` | 新建会话时服务端回传的会话标识,前端保存供后续请求续接 |

### 多轮对话(会话记忆)

- 会话 id 保存在 `localStorage`(`queryforge_session_id`),每次请求自动携带;
- **所有轮次都会被记忆**:查询结果、闲聊回答、无结果均写入服务器端会话历史(最近 5 轮),供「改写问题」节点做指代消解;
- 「新对话」按钮清空会话 id 与消息列表,开启全新会话(服务器端旧会话历史保留);
- 「清空聊天记录」按钮调用 `DELETE /api/sessions` 清除**服务器端全部**会话记忆,
  再清空本地会话标识与消息列表(有确认弹窗);
- 追问时后端「改写问题」节点会结合历史补全问题,步骤条显示
  `改写问题:已结合前文补全为: ...`,让用户感知系统对多轮的理解。

### 图表渲染(ChartView.vue)

- 事件顺序:`result` 事件先到(表格先渲染),随后 `{"stage": "生成图表"}` 阶段事件出现在步骤条,
  最后 `chart` 事件(LLM 根据结果结构建议图表类型与 x/y 字段)把图表附加到**最近一条表格消息**上,
  表格与图表同时展示(图表在上);
- 支持 `bar`(含多系列)、`line`、`pie` 三种图表,由 ECharts 渲染为 canvas;
- **双保险校验**:字段存在性 + 图表类型合法性校验,任一不满足则不渲染图表,仅保留表格;
- `table` 类型或后端未发 chart 事件时,前端行为与旧版完全一致(纯表格)。

### 导出最近一次查询结果

- 「导出最近结果」只读取最近一次 `result` SSE 事件保存的表格列与行,生成 `.xlsx` 文件;
- `chart` 事件中的图表类型及 x/y 字段只用于 ECharts 可视化,完全不参与 Excel 数据生成;
- 每次 `answer` 或 `error` 事件都会清空之前保存的表格,避免导出更早轮次的数据;
- 最近一次回复为非查询回答时,下载包含空白「查询结果」工作表的 Excel,并在页面提示原因;
- 查询结果为 0 行或最近一次查询失败时,同样导出空白 Excel,并显示对应提示;
- 新对话或清空聊天记录后会重置导出状态,不能继续导出旧会话数据;
- Excel 模块仅在点击导出时动态加载,不进入前端首屏主包。

### 交互细节

- 输入框 Enter 或点击「发送」提交,执行中按钮禁用并显示「执行中...」;
- 「导出最近结果」按钮下载最近一次回复对应的表格数据;执行中或尚无回复时按钮禁用;
- 导出完成、空白导出或导出失败均通过非阻塞页面提示条反馈;
- 消息区自动滚动到底部,最新回答始终可见;
- 消息气泡按角色左右分栏(用户右侧、助手左侧),助手带 🤖 头像;
- **数据卡片样式**:表格/图表消息使用独立的宽大白底卡片(`bubble-data`,占消息区 94% 宽度),
  与文本小气泡在视觉上明确区分,图表(360px 高、浅灰底圆角)在上、表格在下,数据成为页面视觉主体;
- 请求正常结束时,步骤条最后一步若仍为执行中状态会统一标记为成功(无图表事件时「生成图表」步骤同样变绿)。

## 与后端协作的协议约定

1. 后端 SSE 每行 `data: {json}`,前端按 `\n\n` 分帧、`data:` 前缀解析;
2. `session_id` 事件是**首个事件**(仅新建会话时回传),客户端保存后随后续请求携带;
3. `chart` 事件永远晚于 `result` 事件到达(后端 execute_sql → chart_suggest 顺序);
4. 图表字段(x/y)必须来自结果列名,否则前端校验失败自动回退;
5. Excel 导出只使用最近一次 `result` 的原始表格数据,不从 `chart` 配置反向生成数据;
6. 单次请求期间只处理当前回答,历史消息不互扰(多轮对话各自独立渲染)。
